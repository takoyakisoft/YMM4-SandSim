# YMM4-SandSim

YMM4向けのGPUサンドシミュレーション映像エフェクトプラグインです。映像・画像をGPU上のセルへ変換し、色と透明度を保ったまま、砂のような落下・崩壊や素材同士の反応を表現します。

## 現在の実装状況

- Direct3D 11 Compute Shader版を実装しています。
- 固定素材をGPU XPBD格子として動かす固体物理を実装しています。CPU剛体エンジンは追加していません。
- 火薬の着火からGPU圧力場を生成し、CA粒子の飛散、XPBD固体への衝撃・破断、爆発光を同じ圧力場から駆動します。
- 火、残り火、溶岩、シーランタン、爆発を光源とするGPU 2Dライティングと、素材による遮蔽を利用したソフトシャドウを実装しています。
- `YMM4SandSim.Tests`で、全素材パラメータの契約、C#/HLSL定数バッファー、CA境界・1D退化ケース、XPBD 4位相による8近傍の網羅、GPUリソースバインディング、csprojとFXCコンパイル対象の一致を検証しています。
- `fxc.exe /O3 /WX`による全12シェーダーの`.cso`生成と、Release/x64プラグインDLLのビルドを確認しています。

## 実装方針

- **Direct3D 11 / Compute Shader 5.0のみ**を使用します。Direct3D 12、ComputeSharp、CPU粒子配列は使用しません。
- CA本体では、色用`R32_UINT` 2枚とメタデータ用`R32_UINT` 2枚を、それぞれping-pong更新します。
- 色はRGBA各8 bitを1個の`uint`へ格納し、素材ID・寿命・イベントビットは別のメタデータ`uint`へ保持します。
- 2×2の重ならないMargolus型ブロックを交互に更新します。論理サイズが奇数の場合はパディング部分だけを固定壁として扱い、幅または高さが1セルの退化ケースでは1D専用更新へ切り替えます。
- CPU readback、`lock`、可変長粒子リストは使用しません。固体の格子占有競合に限り、決定的な所有者選択のためGPU `InterlockedMin`を使用します。
- 入出力には、YMM4と同じDirect3D 11デバイス上の`B8G8R8A8_UNORM`テクスチャを使用します。
- ホットパスでは、LINQ、`List<T>`、`Dictionary<TKey,TValue>`、配列生成、明示的な毎フレーム`Flush`を使用しません。
- CAリソースは、解像度または`粒のサイズ`が変わるまで再利用します。XPBD・爆発・ライト用リソースは、機能に応じて必要時に確保・解放します。
- 固定素材は既定でGPU XPBD格子へ分離し、元画像上の8近傍接続を距離制約として保持します。

## GPU固体物理

`固体物理 = GPU XPBD`では、従来その場に固定されていた素材をCPU剛体へ変換せず、GPU上で連続座標を持つ固体セルとして扱います。

1. 固定素材セルを`RigidState`へ抽出し、通常のセルオートマトンから所有権を外します。
2. Verlet型予測で重力と速度を適用します。
3. 元画像で隣接していた上下左右・斜めのセルへ、XPBD距離制約を反復適用します。4種類の2×2位相を順に処理することで、同一dispatch内の書き込み競合を避けながら8近傍を覆います。
4. 解いた連続座標をセル格子へ再ラスタライズします。同一セルへ複数の固体セルが入る場合は、`InterlockedMin`で不変IDが最も小さいセルを所有者とし、敗者は直前の位置へ戻します。
5. 通常の粉体・液体・気体セルは、この固体占有情報（occupancy）を障害物として参照しながら既存のMargolus更新を続けます。描画時はoccupancyから元の固体色・素材を復元します。
6. 固体は液体密度から簡易浮力・抵抗を受けます。重なりセルと8近傍にある火・溶岩・酸・海水との反応もGPU上で処理します。CA反応で生成された固定素材は、空きsource slotがあればXPBDへ昇格します。

FallingSandJavaの「動く固体のローカル要素をセル行列へ戻す」という構成を参考にしていますが、Javaコード、Box2D/JTS/dyn4jコードは移植していません。AVBD demo2dは反復制約解法と剛体物理の参考にしています。実装自体は、D3D11 Compute Shader向けに独立して実装したXPBDです。

## 爆発

爆発グループの`制御点`を有効にすると、YMM4のプレビュー上に中心と半径の制御点を表示します。中央の制御点をドラッグすると`中心X/Y`、右側の制御点を横方向へドラッグすると`半径`を変更できます。座標はアイテム中心を基準とします。

`発火フレーム`で指定したエフェクト内フレームをまたいだとき、GPU圧力場へ1回だけシードします。同一フレームを再評価しても二重発火しません。シークやパラメータ編集によってシミュレーション状態を再構築した場合は、指定フレーム以降であれば現在の中心から再度シードし、古い状態を残しません。

`中心X/Y`はVTuberKitForYMM4の位置パラメータ規約に合わせ、スライダーを`-500..500 px`、直接入力・アニメーションの保存範囲を`-100000..100000 px`としています。GPUへ渡す際は、実際の最大キャンバス寸法に合わせて安全に正規化します。

すべてのアニメーション値は、負値を取らないパラメータを`0..100000`、負値を取るパラメータを`-100000..100000`の範囲で保存します。スライダーには、操作しやすい初期範囲を別に設けています。倍率系の%は最大`400%`、基本の`強さ`・流動性・ライトの`明るさ`・影・抽出の閾値は`0..100%`を表示します。GPUへ渡す値は、各機能の安全な実効範囲へ正規化します。

火・残り火・溶岩などが火薬へ着火した場合も、セルのメタデータに1回だけ消費される爆発イベントを設定します。手動爆心と自然着火は同じGPU圧力場を使用します。CPUイベントリストは作らず、GPU上の`R32_FLOAT`圧力テクスチャ2枚をping-pong更新して衝撃波を伝播します。

- 圧力はCAの1 iterationあたり約1セルずつ広がり、爆発グループの`半径`に応じて減衰します。瞬間的に円形範囲を削除する方式ではありません。
- 着火した火薬の爆発イベントは、圧力パスが消費するまでそのセルへ固定します。これにより、反応・重力・横移動・爆風swapによって爆心がずれたり消えたりすることを防ぎます。
- 強い圧力波が別の火薬へ到達すると、そのセルも次のiteration用の爆発イベントを発生させるため、連鎖爆発します。
- 圧力勾配は粉体・液体・気体を低圧側へ押し、同じ勾配をXPBD固体の速度とbondの破断にも使用します。
- 圧力透過率は、おおむね`気体 > 液体 > 粉体 > 有機固体 > 鉱物/金属`です。1セル厚の脆い壁には衝撃が入り、厚く密度の高い壁ほど背後を遮蔽します。斜め方向には、2つの直交側セルの少なくとも一方を通れる場合だけ強く伝播します。そのため、閉じた90度角を爆風が斜めにすり抜けにくくしています。
- 爆発圧力はライティング側でも暖色の短いフラッシュとして使用します。これにより、飛散・破断・発光が同じGPU状態から同期します。

## ライティングと影

描画時にGPUライトフィールドを生成し、CA/XPBDの現在位置をそのまま遮蔽物として使用します。

1. 火、残り火、溶岩、シーランタン、爆発圧力からRGB発光をシードします。
2. ライトグループの`半径`回、8近傍へライトフィールドをping-pong伝播します。
3. 伝播元の素材ごとに透過率を掛けます。気体・水は光を通しやすく、煙・インク・粉体では減衰し、石・金属では強く遮られます。コバルトガラス、氷、石英、ワックスなどは専用の半透明透過率を持ちます。
4. 固体表面は光を受けられますが、光は固体内部を通りにくいため、背後にソフトな2D影ができます。斜め方向の光も閉じた90度角を直接すり抜けないよう、直交側セルの透過率を確認します。
5. 最終描画では、ライトグループの`明るさ=100%`で元の素材・入力映像の明るさを維持し、伝播した発光を上乗せします。通常部分を暗くしなくても、火・溶岩・シーランタン・爆発の明るさを感じられます。ライトの`強さ=0%`なら従来表示、`100%`を超えると発光側をさらに強調します。

これは画面空間セル上の決定論的な近似であり、レイトレーシングや物理ベースの放射輸送ではありません。可変長のlight list、CPU readback、追加の同期`lock`は使用しません。

## 入力モード

### 初期フレームを素材化（既定）

最初のフレーム、またはシーク後のフレームを初期状態として取り込み、以降はGPU状態だけを進めます。通常の崩壊演出向けです。

### 空セルに毎フレーム追加

毎フレームの映像から、現在空いているセルだけへ素材を追加します。CAだけでなく、現在のXPBD固体occupancyも占有として扱います。そのため、動いた固体の下へ新しい粉体・液体を重ねて注入しません。透明背景の文字、立ち絵、パーティクル映像などを発生源として利用できます。

抽出しきい値をアニメーションしても、それ以前に蓄積した素材は消去せず、新たに注入するセルだけへ反映します。XPBD固定素材は1入力セルにつき1つのrigid source slotを使用するため、そのslotが移動中は、同じソースセルから固定素材を重複生成しません。

### 選択位置へ毎フレーム再配置

毎フレームの入力映像で、選択された位置を再スタンプします。選択位置は現在のフレームに追従し、それ以外の場所へ移動・蓄積したCA状態は保持します。XPBD固定素材の既存source slotは入力位置へ戻しますが、すでに破断したbondは自動では再接着しません。

全面を再生成せず、選択位置だけを再配置するため、動画へ追従させながらシミュレーション履歴も残せます。

## タイムライン動作

- 基本グループの`強さ`は合成率だけを変更します。`0%`でも内部のCA/XPBD状態はタイムラインどおり進み、あとから値を戻してもシミュレーションを再初期化しません。
- 同一フレームを複数回評価しても、変更がなければシミュレーションは二重に進みません。
- 同一フレームで速度、横崩れ、抽出条件などを変更した場合は、古いGPU結果を使い回さず再計算します。
- 基本グループの`強さ`だけを変更しても、シミュレーション状態は破棄しません。
- 連続フレームでは状態を保持します。
- 逆再生、ジャンプ、シーク、解像度または`粒のサイズ`の変更では、その位置の入力映像から再初期化します。
- 任意位置へのシーク時に、過去の全フレームを再計算する方式は採用していません。編集プレビューを重くしないためです。

## 推奨設定

- 1920×1080: `粒のサイズ=4 px`、`更新回数=4回`
- 細部優先: `粒のサイズ=2 px`
- 4Kまたは複数同時使用: `粒のサイズ=6～8 px`

GPU状態は機能ごとに必要時に確保します。CA本体は約16 byte/cell、XPBDを有効にするとさらに44 byte/cell、爆発は8 byte/cell、ライティングは8 byte/cellを使用し、全機能有効時は約76 byte/cellです。1920×1080・1 pxでは、CAのみで約31.6 MiB、全機能有効時で約150.3 MiBです。4 pxでは約9.4 MiBです。入力・出力テクスチャ、Direct2D参照、ドライバー管理分は含みません。

状態予算は約304 MiBに固定し、実際に有効な機能のbyte/cellから許容セル数を計算します。そのため、4K・1 pxでもCAのみなどの軽い構成なら使用できますが、全機能有効時は2 px以上が必要です。ライト半径はGPU計算量にもほぼ比例するため、4 px・12セルを既定にしています。

## Windowsでのビルド

必要なもの：

- Windows 10/11 x64
- .NET 10 SDK
- YMM4本体フォルダー内の参照DLL一式
- Windows SDKの`fxc.exe`
- Direct3D Feature Level 11_0以上のGPU

ローカル固有のパスはGitへコミットしません。初回だけサンプルをコピーし、作成した`Directory.Build.props`を自分の環境に合わせて編集します。

```powershell
Copy-Item .\Directory.Build.props.sample .\Directory.Build.props
notepad .\Directory.Build.props
```

`YMM4DirPath`、`FxcPath`、`DotnetPath`、`PythonPath`を設定します。ローカルパスは、すべて`Directory.Build.props`だけに記述します。

シェーダーを含むRelease/x64ビルドとYMM4への配置：

```powershell
.\scripts\dev.ps1
```

通常は次の場所へ配置されます。

```text
<YMM4Dir>\user\plugin\YMM4SandSim\YMM4SandSim.dll
```

診断ログは同じフォルダーの`YMM4SandSim.log`へ出力されます。単一ファイルが2 MiBを超えると古い行を削除し、末尾約1 MiBを保持します。Releaseビルドでは起動メタデータを1行記録し、その後は`Error`のみを記録します。Debugビルドでは`Information`が既定です。必要に応じて、環境変数`YMM4SANDSIM_LOG_LEVEL`に`Debug`、`Information`、`Warning`、`Error`のいずれかを設定できます。

`Directory.Build.props`を作成済みなら、直接`dotnet`でビルド・テストする場合もローカル設定が自動的に読み込まれます。

```powershell
dotnet build .\YMM4SandSim\YMM4SandSim.csproj -c Release -p:Platform=x64
```

## テスト

静的契約テストとxUnitテストを実行します。

```powershell
.\scripts\dev.ps1 test
```

整形・自動修正は`.\scripts\dev.ps1 format`、リント・自動修正は`.\scripts\dev.ps1 lint`で実行します。

検証内容：

- 55色パレットと57素材ID、移動クラス、素材別XPBD・流体パラメータの整合性
- 偶数・奇数の論理解像度、1セル幅・高さ、パディング境界で、全セルを重複なく更新すること
- XPBD 4位相で8近傍bondを過不足なく解き、破断・浮力・CA反応・occupancy契約を維持すること
- 爆発イベント・圧力場とライト・影の伝播、閉じた角の遮蔽、GPUのみで完結するリソース契約
- 同一フレーム再評価、設定変更、シーク、各入力モードの状態遷移
- 不正な列挙値の正規化、UI上限と実行時上限、機能別GPU状態予算
- C#とHLSLの定数バッファー、csprojとFXC対象、シェーダー構文上の静的契約

## リリースと翻訳

リリース番号は[Directory.Build.targets](Directory.Build.targets)の`YMM4SandSimVersion`だけを変更します。`v0.4.0`のように同じ番号のタグをpushすると、GitHub Actionsが最新YMM4を取得してRelease/x64をビルドし、`.ymme`を内包した配布用ZIPをGitHub ActionsのArtifactsとGitHub Releasesへ登録します。

ローカルでビルド・配置・パッケージ生成をまとめて行う場合：

```powershell
.\scripts\dev.ps1 publish
```

成果物は`artifacts/YMM4SandSim-v<version>.zip`です。ZIP内には、インストーラー用`.ymme`と`Readme.txt`が入ります。

UI翻訳は`YMM4SandSim/Localization/Translate.csv`を編集します。サブモジュールの`YukkuriMovieMaker.Generator`がビルド時に`.resx`とリソース型を生成するため、生成された`.resx`は直接編集しません。初回取得時は次を実行します。

```powershell
git submodule update --init --recursive
```

## 制約

- 57素材の粉体・液体・気体・固定素材分類を持ちます。GPU XPBDを有効にした場合、固定素材は動的な固体格子として扱われます。
- シミュレーションは入力画像の矩形内で行い、固体物理も矩形境界を越えません。
- 固体とCAは、occupancy、簡易浮力・流体抵抗、燃焼・融解・腐食・酸化、CA生成固定素材のXPBD昇格、爆発圧力・破断までGPU上で連携します。液体の体積押し出し・連続流体圧力、粉体を剛体が能動的に押し退ける処理、完全な流体-固体接触はいずれも近似実装です。
- 影はセル上の反復光伝播によるソフトシャドウです。点光源ごとの厳密な可視性判定やレイトレーシングは行いません。
- GPU状態を過去へ戻すチェックポイントキャッシュは持ちません。
- Windows実機では、YMM4の描画スレッドとの共存、GPUドライバー差、デバイスロスト、実際のフレーム順序を確認する必要があります。

- YMM4プラグイン構造は、添付された`YMM4-MultiscaleRetinex`を参照しました。
- 砂シミュレーションの要件と色保持の考え方は、添付された`EP01_SandSim`を参照しました。元実装はCPUシミュレーションであり、本プロジェクトのGPU更新器は新規実装です。

- AVBD demo2d（MIT）は制約ベース物理の参考資料として確認しました。本実装はAVBDコードの移植ではなく、GPU XPBD距離制約による独立実装です。
- Noita / Falling Everything Engineの公開説明は、爆発・発光・遮蔽をセル物理と同じ世界状態へ結びつける挙動上の参考にしています。Noitaの非公開エンジンコードや内部ライティング実装は使用していません。
- 各参照元のライセンスは`LICENSES`に収録しています。
