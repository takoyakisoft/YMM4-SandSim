# YMM4-SandSim

YMM4の映像や画像をGPU上のセルへ変換し、色と透明度を保ったまま、砂、液体、気体、固体として動かす映像エフェクトプラグインです。
57種類の物理素材を扱い、55色のパレットから素材を自動判定するほか、単一素材として指定することもできます。

砂のように崩すだけではありません。
固定素材の落下や変形、破断、火薬の連鎖爆発、発光と影まで、同じセル世界の状態を使ってGPU上で処理します。

## できること

- 入力映像の色と透明度を保ったまま、粉体、液体、気体、固定素材へ変換します。
- 固定素材をGPU XPBD格子として動かし、落下、変形、衝突、破断を処理します。
- 火薬の着火からGPU圧力場を生成し、CA素材の飛散、XPBD固体への衝撃、破断、爆発光を連動させます。
- 火、残り火、溶岩、シーランタン、爆発を光源として、素材による遮蔽を反映した2Dライティングとソフトシャドウを生成します。
- 初期フレームだけを素材化するほか、空セルへの継続追加、選択位置への毎フレーム再配置にも対応します。
- 同一フレームの再評価では状態を二重に進めず、シーク時はその位置の入力から状態を再構築します。

実装はDirect3D 11 Compute Shaderを中心に構成しています。
CPUへセル状態を読み戻して物理計算する方式ではなく、CA、固体物理、爆発、ライティングの主要処理をGPU上で完結させています。

## インストール

配布ZIPに含まれる`YMM4SandSim-*.ymme`をダブルクリックし、YMM4の案内に従ってインストールしてください。

手動で導入する場合は、プラグイン一式を次のフォルダーへ配置します。

```text
<YMM4Dir>\user\plugin\YMM4SandSim
```

問題が発生した場合は、同じフォルダーに出力される`YMM4SandSim.log`を確認してください。

## 実装方針

- **Direct3D 11 / Compute Shader 5.0のみ**を使用します。
  Direct3D 12、ComputeSharp、CPU粒子配列は使用しません。
- CA本体は、色用`R32_UINT` 2枚とメタデータ用`R32_UINT` 2枚を、それぞれping-pongします。
- 色はRGBA 8 bitを1個の`uint`へ格納し、素材ID、寿命、イベントbitは別のメタデータ`uint`へ保持します。
- 2×2の重ならないMargolus型ブロックを交互に更新します。
  奇数の論理サイズではパディング部分だけを固定壁として扱い、幅または高さが1セルの退化ケースでは1D専用更新へ切り替えます。
- CPU readback、`lock`、可変長粒子リストは使用しません。
  固体の格子占有競合に限り、決定的な所有者選択のためGPU `InterlockedMin`を使用します。
- 入力と出力には、YMM4と同じDirect3D 11デバイス上の`B8G8R8A8_UNORM`テクスチャを使用します。
- ホットパスでは、LINQ、`List<T>`、`Dictionary<TKey,TValue>`、配列生成、明示的な毎フレーム`Flush`を使用しません。
- CAリソースは、解像度または粒のサイズが変わるまで再利用します。
  XPBD、爆発、ライト用リソースは、各機能が必要な場合だけ確保します。
- 固定素材は既定でGPU XPBD格子へ分離し、同一素材かつ4近傍で実際につながっている未破断領域をGPU Connected ComponentsでBody化します。斜めを含むXPBD距離制約は同じBody内だけで解きます。

## GPU固体物理

「固体物理」を有効にすると、従来はその場に固定されていた素材を、CPU剛体へ変換せずGPU上の連続座標を持つ固体セルとして扱います。
方式にはXPBD（Extended Position Based Dynamics）を使用します。

1. 固定素材セルを`RigidState`へ抽出し、通常のセルオートマトンから所有権を外します。
2. Verlet型予測で重力と速度を適用します。
3. 同一素材の4近傍接続と未破断bondからGPU上でConnected Componentsを構築し、離れた同素材や異素材を別Body IDに分離します。
4. 同じBody ID内だけで上下左右と斜めのXPBD距離制約を反復適用します。
   4種類の2×2位相を順に処理し、同一dispatch内の書き込み競合を避けながら8近傍を覆います。
5. 解いた連続座標をセル格子へ再ラスタライズします。
   同一セルへ複数の固体セルが入る場合は`InterlockedMin`で所有者を決めます。外部接触はBody全体へ軸別に共有し、床では縦方向、壁では横方向の速度だけを止めて接線方向の運動量を残します。
6. 空洞はEmptyセルのままなので、巨大な1Bodyでも内部の穴や通路に当たり判定は生成されません。
7. 粉体、液体、気体は、この固体occupancyを障害物として参照しながらMargolus更新を続けます。
   描画時はoccupancyから元の固体色と素材を復元します。
8. 固体は液体密度から簡易浮力と抵抗を受け、重なりセルと8近傍にある火、溶岩、酸、海水との反応もGPU上で処理します。
   CA反応で生成された固定素材は、空きsource slotがあればXPBDへ昇格します。

FallingSandJavaの「動く固体のローカル要素をセル行列へ戻す」という構成は、設計上の参考にしています。
Javaコード、Box2D、JTS、dyn4jのコードは移植していません。

AVBD demo2dは、反復制約解法と剛体物理の構成を確認するために参照しました。
本実装はD3D11 Compute Shader向けの独立したXPBD実装です。

## 爆発

爆発グループの`制御点`を有効にすると、YMM4のプレビュー上に爆発の中心と半径を示す制御点が表示されます。
中央の制御点をドラッグすると`中心X/Y`を変更でき、右側の制御点を横方向へドラッグすると`半径`を変更できます。
座標はアイテム中心基準です。

`発火フレーム`で指定したエフェクト内フレームをまたぐと、制御点爆発を1回だけ開始します。
同一フレームを再評価しても二重発火しません。制御点爆発は火薬用の遅い圧力伝播とは分離され、ユーザー指定の円半径を約6 simulation iterationで横切る解析的なEuclidean衝撃波として処理します。
シークやパラメータ編集によってシミュレーション状態を再構築した場合は、指定フレーム以降であれば現在の中心から再度開始し、再構築前の状態は残しません。

`中心X/Y`はVTuberKitForYMM4の位置パラメータ規約に合わせ、スライダーを`-500..500 px`、直接入力とアニメーションの保存範囲を`-100000..100000 px`としています。
GPUへ渡す中心座標は画面端へclampしません。爆心を画面外へ置き、半径の一部だけを画面内へ届かせる指定もそのまま反映します。

アニメーション値は、負値を取らないパラメータを`0..100000`、負値を取るパラメータを`-100000..100000`の範囲で保存します。
スライダーには操作しやすい初期範囲を別に設け、倍率系の%は最大`400%`、基本の`強さ`、流動性、ライトの`明るさ`、影、抽出の閾値は`0..100%`を表示します。
GPUへ渡す値は、機能ごとの安全な実効範囲へ正規化します。

火、残り火、溶岩などが火薬へ着火した場合は、セルのメタデータに1回だけ消費される爆発イベントを設定します。火薬由来の爆発だけはGPU上の`R32_FLOAT`圧力テクスチャ2枚をping-pongし、素材を通って伝播する圧力場として扱います。

- **制御点爆発**は解析的な円形frontを約6 simulation iterationで最大半径まで進めます。CA、XPBD、発光は同じEuclidean frontを参照するため、大半径でも遅いセル伝播にはなりません。
- **火薬爆発**は1セルのイベントから8近傍の圧力場へ伝播し、壁や素材の透過率を受けながら連鎖爆発します。
- XPBD固体は制御点爆発ではConnected Body単位の共通放射impulse、火薬爆発では圧力勾配からのimpulseを受けます。
- 制御点爆発は中心を空洞化し、空洞壁の狭いshellへFireを生成します。延焼は既存のCA反応で進みます。
- 制御点爆発の破断スケールは爆発半径から分離し、ガラス/氷は細かく、石系は中程度、木や金属は大きな塊を保つ素材別スケールを使用します。
- 着火した火薬の爆発イベントは、圧力パスが消費するまでそのセルへ固定します。
  反応、重力、横移動、爆風swapによって爆心がずれたり消えたりすることを防ぎます。
- 強い圧力波が別の火薬へ到達すると、そのセルも次iteration用の爆発イベントを発生させるため、連鎖爆発します。
- 圧力勾配は粉体、液体、気体を低圧側へ押し、同じ圧力場をXPBD固体の速度とbond破断にも使用します。
- 圧力透過率は、おおむね`気体 > 液体 > 粉体 > 有機固体 > 鉱物/金属`です。
  1セル厚の脆い壁には衝撃が入り、厚い壁や密度の高い壁ほど背後への圧力を弱めます。
  斜め方向では、2つの直交側セルの少なくとも一方を通れる場合だけ強く伝播するため、閉じた90度角を爆風が斜めにすり抜けにくくしています。
- 爆発圧力はライティング側でも使用し、進行中の波面を暖色のリングとして強調します。
  飛散、破断、発光は同じGPU状態から同期します。

## ライティングと影

描画時にはGPUライトフィールドを生成し、CAとXPBDの現在位置をそのまま遮蔽物として使用します。

1. 火、残り火、溶岩、シーランタン、爆発圧力からRGB発光をシードします。
2. ライトグループの`半径`回、8近傍へライトフィールドをping-pong伝播します。
3. 伝播元の素材ごとに透過率を掛けます。
   気体と水は光を通しやすく、煙、インク、粉体は強く減衰し、石と金属はさらに強く遮ります。
   コバルトガラス、氷、石英、ワックスなどは専用の半透明透過率を持ちます。
4. 固体表面は光を受けますが、その光は固体内部を通りにくいため、背後にソフトな2D影ができます。
   斜め方向の光も閉じた90度角を直接すり抜けないよう、直交側セルの透過率を確認します。
5. ライトグループの`明るさ=100%`では、元の素材と入力映像の明るさを維持したまま、伝播した発光を上乗せします。
   通常部分を暗くしなくても、火、溶岩、シーランタン、爆発の発光を確認できます。
   ライトの`強さ=0%`なら従来表示となり、100%を超えると発光側をさらに強調します。

この処理は、画面空間のセル上で行う決定的な近似です。
レイトレーシングや物理ベースの放射輸送ではありません。
可変長light list、CPU readback、追加の同期`lock`も使用しません。

## 入力モード

### 初期フレームを素材化（既定）

最初に評価したフレーム、またはシーク後に再構築したフレームを初期状態として取り込み、その後はGPU状態だけを進めます。
通常の崩壊演出にはこのモードを使用します。

### 空セルに毎フレーム追加

毎フレームの入力映像から、現在空いているセルだけへ素材を追加します。
CAだけでなく現在のXPBD固体occupancyも占有として扱うため、動いた固体の下へ新しい粉体や液体を重ねて注入しません。
透明背景の文字、立ち絵、パーティクル映像などを継続的な発生源として利用できます。

抽出しきい値をアニメーションしても、それ以前に蓄積した素材は消去しません。
変更後の条件は、新たに注入するセルだけへ反映します。

XPBD固定素材は1入力セルにつき1つのrigid source slotを使用します。
そのslotが移動中であれば、同じソースセルから固定素材を重複生成しません。

### 選択位置へ毎フレーム再配置

毎フレームの入力映像で、選択された位置を再スタンプします。
選択位置は現在フレームへ追従し、それ以外の場所へ移動、蓄積したCA状態は保持します。
XPBD固定素材の既存source slotは入力位置へ戻しますが、すでに破断したbondは自動では再接着しません。

全面を再生成せず、選択位置だけを再配置します。
動画へ追従させながらシミュレーション履歴を残したい場合に使用できます。

## タイムライン動作

YMM4は編集中に同じフレームを複数回評価したり、任意位置へシークしたりします。
シミュレーションが評価回数そのものに依存すると、プレビューと動画出力で結果が変わるため、フレームの進み方を判定して状態を管理します。

- 基本グループの`強さ`は合成率だけを変更します。
  `0%`でも内部のCAとXPBD状態はタイムラインどおり進み、あとから値を戻してもシミュレーションを再初期化しません。
- 同一フレームを複数回評価しても、設定変更がなければシミュレーションは二重に進みません。
- 同一フレームで速度、横崩れ、抽出条件などを変更した場合は、古いGPU結果を使い回さず再計算します。
- 基本グループの`強さ`だけを変更しても、シミュレーション状態は破棄しません。
- 連続フレームでは状態を保持します。
- 逆再生、ジャンプ、シーク、解像度変更、`粒のサイズ`変更では、その位置の入力映像から再初期化します。
- 任意位置へのシーク時に、過去の全フレームを再計算する方式は採用していません。
  編集プレビューの負荷を抑えるためです。

## 推奨設定とGPUメモリ

- 1920×1080：`粒のサイズ=4 px`、`更新回数=4回`
- 細部を優先する場合：`粒のサイズ=2 px`
- 4Kまたは複数同時使用：`粒のサイズ=6～8 px`

GPU状態は機能ごとに必要な場合だけ確保します。
CA本体は約16 byte/cell、XPBDを有効にするとBody label/contactを含め約52 byte/cell、爆発は8 byte/cell、ライティングは8 byte/cellが追加され、全機能有効時は約84 byte/cellです。

1920×1080、1 pxでは、CAのみで約31.6 MiB、全機能有効時で約166.1 MiBです。
4 pxなら全機能有効時でも約10.4 MiBです。
これらには入力と出力のテクスチャ、Direct2D参照、ドライバー管理分を含みません。

状態予算は約304 MiBです。
有効な機能ごとのbyte/cellから許容セル数を計算するため、4K、1 pxでもCAのみのような軽い構成なら使用できますが、全機能有効時は2 px以上が必要です。
ライト半径はGPU計算量にもほぼ比例するため、4 px、12セルを既定値としています。

### 性能診断

Releaseビルドの通常ログはErrorのままです。性能調査時だけ環境変数`YMM4SANDSIM_LOG_LEVEL=Information`を設定すると、120回ごとにsimulation/renderのCPU submit時間とCompute Shaderのdispatch回数を`YMM4SandSim.log`へ記録します。

ログの`cpuSubmitMs`はD3D11コマンドをCPUから発行した時間で、GPU実行時間ではありません。GPU stateのreadbackや待機は追加していないため、GPU本体のボトルネックはPIX/RenderDocなど外部GPU profilerと併用して確認してください。

Connected Componentsのunion/compress passはshader、SRV、UAVをround間で保持し、constant bufferだけを切り替えてD3D11 state changeを減らしています。

## Windowsでのビルド

必要な環境は次のとおりです。

- Windows 10 / 11 x64
- .NET 10 SDK
- YMM4本体フォルダー内の参照DLL一式
- Windows SDKの`fxc.exe`
- Direct3D Feature Level 11_0以上のGPU

ローカル固有のパスはGitへコミットしません。
初回だけサンプルをコピーし、作成した`Directory.Build.props`を自分の環境に合わせて編集します。
`Directory.Build.props`は`.gitignore`の対象です。

```powershell
Copy-Item .\Directory.Build.props.sample .\Directory.Build.props
notepad .\Directory.Build.props
```

`YMM4DirPath`、`FxcPath`、`DotnetPath`、`PythonPath`を設定します。
ローカルパスはすべて`Directory.Build.props`だけに置きます。

シェーダーを含むRelease/x64ビルドとYMM4への配置は、次のコマンドで実行します。

```powershell
.\scripts\dev.ps1
```

通常は次の場所へ配置されます。

```text
<YMM4Dir>\user\plugin\YMM4SandSim\YMM4SandSim.dll
```

診断ログは同じフォルダーの`YMM4SandSim.log`へ出力されます。
単一ファイルが2 MiBを超えると古い行を削除し、末尾約1 MiBを保持します。
Releaseビルドでは起動メタデータを1行記録し、その後はErrorだけを記録します。
DebugビルドはInformationが既定で、必要に応じて環境変数`YMM4SANDSIM_LOG_LEVEL`へ`Debug`、`Information`、`Warning`、`Error`のいずれかを設定できます。

`Directory.Build.props`を作成済みなら、直接`dotnet`を実行する場合もローカル設定が読み込まれます。

開発用コマンドは次の構成です。`fmt`と`format`は同じ動作で、`check`は整形、リント、テストを順に実行します。`clean`はリポジトリ内のビルド出力、生成済みシェーダー、配布成果物を削除します。

```powershell
.\scripts\dev.ps1             # build
.\scripts\dev.ps1 test
.\scripts\dev.ps1 fmt
.\scripts\dev.ps1 lint
.\scripts\dev.ps1 check
.\scripts\dev.ps1 clean
.\scripts\dev.ps1 publish
```

```powershell
dotnet build .\YMM4SandSim\YMM4SandSim.csproj -c Release -p:Platform=x64
```

## テスト

静的契約テストとxUnitテストは、次のコマンドで実行します。

```powershell
.\scripts\dev.ps1 test
```

整形と自動修正は`.\scripts\dev.ps1 fmt`（または`format`）、変更を加えないリント検証は`.\scripts\dev.ps1 lint`で実行できます。GitHub ActionsのCIは`fmt -Verify`と`lint`だけを実行します。

主な検証対象は次のとおりです。

- 55色パレットと57素材ID、移動クラス、素材別XPBDパラメータ、流体パラメータの整合性
- 偶数と奇数の論理解像度、1セル幅と1セル高さ、パディング境界で、全セルを重複なく更新すること
- 同一素材4近傍のConnected Body分離、Body内XPBD 8近傍bond、破断、軸別接触、浮力、CA反応、occupancyの契約を維持すること
- 爆発イベント、圧力場、ライト、影の伝播、閉じた角の遮蔽、GPU-onlyリソースの契約
- 同一フレーム再評価、設定変更、シーク、各入力モードの状態遷移
- 不正な列挙値の正規化、UI上限とruntime上限、機能別GPU状態予算
- C#とHLSLの定数バッファー、csprojとFXC対象、シェーダー構文の静的契約

## リリースと翻訳

リリース番号は[Directory.Build.targets](Directory.Build.targets)の`YMM4SandSimVersion`だけを変更します。
`v0.4.0`のように同じ番号のタグをpushすると、GitHub Actionsが最新のYMM4を取得してRelease/x64をビルドし、`.ymme`を含む配布用ZIPをArtifactsとGitHub Releasesへ登録します。

ローカルでビルド、配置、パッケージ生成をまとめて行う場合は、次のコマンドを実行します。

```powershell
.\scripts\dev.ps1 publish
```

成果物は`artifacts/YMM4SandSim-v<version>.zip`です。
ZIPにはインストーラー用`.ymme`と`Readme.txt`が含まれます。

UI翻訳は`YMM4SandSim/Localization/Translate.csv`を編集します。
サブモジュールの`YukkuriMovieMaker.Generator`がビルド時に`.resx`とリソース型を生成するため、生成された`.resx`は直接編集しません。

初回取得時はサブモジュールも取得します。

```powershell
git submodule update --init --recursive
```

## 制約

- 57種類の素材を粉体、液体、気体、固定素材として扱います。
  GPU XPBDが有効な場合、固定素材は動的な固体格子として処理されます。
- シミュレーションは入力画像の矩形内で行い、固体物理も矩形境界を越えません。
- 固体とCAは、occupancy、簡易浮力と流体抵抗、燃焼、融解、腐食、酸化、CA生成固定素材のXPBD昇格、爆発圧力、破断までGPU上で連携します。
  液体の体積押し出しと連続流体圧力、粉体を剛体が能動的に押し退ける処理、完全な流体と固体の接触は、現在も近似です。
- 影はセル上の反復光伝播によるソフトシャドウです。
  点光源ごとの厳密な可視性判定やレイトレーシングは行いません。
- GPU状態を過去へ戻すチェックポイントキャッシュは持ちません。
- Windows実機では、YMM4の描画スレッドとの共存、GPUドライバー差、デバイスロスト、実際のフレーム順序を確認する必要があります。
